# Data directory

This directory holds three kinds of data, with very different status.

## `sample/quarterly_metrics.csv`  bundled, deterministic, illustrative

144 project-quarters (6 projects 24 quarters), generated by
`src/generate_sample.py` from per-project trajectory profiles
calibrated against publicly-documented project characteristics. Not
fetched from GitHub.

The bundled sample exists so that reviewers can run
`bash run.sh` and see end-to-end results in 10 seconds without
needing a GitHub token. It is *not* a substitute for live data;
verifying the methodology against live GitHub responses is the
purpose of `src/fetch_github.py`.

The trajectories are documented in `src/generate_sample.py` near the
`PROJECT_PROFILES` dictionary. They are deterministic  the same
input seed produces the same output bytes, modulo Python build
differences in `hash()`.

## `raw/{project_id}.jsonl`” live, only present after fetch

Empty in the bundled repository. Populated by running
`python src/fetch_github.py` with a `GITHUB_TOKEN` environment variable.
Each file is one project's full event log every merged PR with
created/merged timestamps and add/del counts, plus every release within
the study window. JSON-lines format, one event per line, with a
`_meta` header on the first line.

These files are large (10-50 MB each for big projects). They are
listed in `.gitignore` and should never be committed.

## `derived/quarterly_metrics.csv` live, only present after compute

Empty in the bundled repository. Populated by running
`python src/compute_metrics.py` after the fetch. Same shape as
`sample/quarterly_metrics.csv` but computed from real GitHub events.

When `derived/quarterly_metrics.csv` exists, `run_analysis.py` uses it
in preference to `sample/quarterly_metrics.csv`, and the auto-generated
`results/REPORT.md` reports `Data source: live` at the top.

---

## Verification path for reviewers

```bash
export GITHUB_TOKEN=ghp_xxx
python src/fetch_github.py            # ~5-15 minutes
python src/compute_metrics.py         # seconds
bash run.sh                           # uses live data automatically
diff <(jq . results/discriminative_power.json) <previous-sample-version>
```

Differences between the live-data and bundled-sample numbers are
expected (the sample is illustrative). What matters for replication is
that the *direction* and *significance* of the era effects are
preserved across both paths.
