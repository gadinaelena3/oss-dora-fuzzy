# Reproducibility

Reviewer-facing checklist. Every number reported in `results/REPORT.md`
and every figure in `results/plots/` can be regenerated by running one
command. Tested on macOS 14, Ubuntu 22.04, and Windows 11 (WSL2) with
Python 3.11.

> Note. The bundled sample dataset (`data/sample/quarterly_metrics.csv`)
> is generated by `src/generate_sample.py` from documented per-project
> trajectory profiles, not fetched from GitHub. The fetcher is
> provided for reviewers who want to verify against live data; both
> paths run through identical analysis code.

---

## 1. Environment

You need:

- Python 3.11.x
- The dependencies pinned in `requirements.txt`

That's it. No Docker, no Node, no GitHub token (unless you choose to
verify against live data).

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## 2. Reproducing the bundled-sample analysis

```bash
bash run.sh
```

That single command runs three steps:

1. `python src/generate_sample.py` â†’ regenerates the deterministic
   sample dataset in `data/sample/quarterly_metrics.csv`.
2. `python src/run_analysis.py` â†’ applies the fuzzy DSS, computes
   statistics, writes `results/*.csv`, `results/discriminative_power.json`,
   and `results/REPORT.md`.
3. `python src/make_plots.py` â†’ writes the four figures to
   `results/plots/`.

Total runtime: roughly 10 seconds.

Expected output:

```
Wrote 144 project-quarters to .../data/sample/quarterly_metrics.csv
Loaded 144 project-quarters from sample dataset.
Applying fuzzy DSS to every row...
 results/phs_timeseries.csv
Computing pre-AI vs AI-era comparison...
 results/era_comparison.csv
Computing discriminative power...
 results/discriminative_power.json
Building human-readable report...
 results/REPORT.md
Generating plots:
  fig1_phs_timeseries.png
  fig2_era_boxplot.png
  fig3_state_heatmap.png
  fig4_input_drift.png
```

The numbers in `results/discriminative_power.json` should match those
quoted in the paper's 5 verbatim. If they do not, the sample-data
generator has been edited.

## 3. Verifying against live GitHub data

This is the path Reviewer #1 implicitly asks for. It requires a
GitHub personal access token (no special scopes are needed for public
repos).

### 3.1 Get a token

1. Visit <https://github.com/settings/tokens>.
2. Click "Generate new token (classic)".
3. Leave all scopes unchecked (we only read public data).
4. Copy the token value.

### 3.2 Run the fetcher

```bash
export GITHUB_TOKEN=ghp_xxx                # use your token
python src/fetch_github.py                 # fetches all six projects
# or:
python src/fetch_github.py vscode          # one project at a time
```

Each project produces `data/raw/{project_id}.jsonl` containing every
merged PR and release in the study window. Expect ~2,000-8,000 PRs per
project; the fetcher caches incrementally so an interrupted run can
resume.

### 3.3 Re-derive metrics and re-analyse

```bash
python src/compute_metrics.py     # raw â†’ data/derived/quarterly_metrics.csv
python src/run_analysis.py        # â†’ results/* (now uses live data)
python src/make_plots.py
```

`run_analysis.py` automatically prefers `data/derived/quarterly_metrics.csv`
over the bundled sample. The auto-generated `results/REPORT.md` will
say `Data source: live` at the top so you know which dataset
produced the numbers.

## 6. If something fails

- `ModuleNotFoundError: skfuzzy` `pip install scikit-fuzzy` (note
  the `-` and the dist-name vs import-name difference).
- `requests.exceptions.HTTPError: 401` from the fetcher  your token
  is wrong or expired.
- `requests.exceptions.HTTPError: 403` rate limit. The fetcher
  sleeps automatically when remaining < 100; if you still see this,
  the token may not have public-repo read permission.
- `results/REPORT.md` says `Data source: sample` when you wanted
  live  `data/derived/quarterly_metrics.csv` doesn't exist yet, so
  the analysis fell back. Run `python src/compute_metrics.py` after
  the fetch to produce it.

## 7. What "deterministic" means for the bundled sample

`src/generate_sample.py` seeds `numpy.random.default_rng` with
`hash(project_id) & 0xFFFFFFFF` for each project. Running the script
twice on the same machine (and the same Python build) produces
byte-identical output. Different Python builds may produce different
hashes; in that case the *trajectories* are the same but the *noise*
realisation differs. The aggregate statistics (per-project means,
era shifts, Kruskal-Wallis) are stable to within a few PHS points
across builds.

If absolute byte-equality matters for your review, run the bundled
sample on the Docker image used in the parent fuzzy-dss repo
(`python:3.11-slim` base).
